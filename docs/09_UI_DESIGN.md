## 1. 目的和范围

Vegeta 的三个界面用**同一套设计规则**，当前官网为 https://vegeta-ops.vercel.app/ ：

| 界面 | 仓库 | 性质 |
|---|---|---|
| Goten — Deal Calculations（对账、关闭、分配） | `deal-ops-toolkit`（`src/`） | 工作界面 |
| Trunks — Operations Inbox 审核界面 | 本仓库（`src/web/`） | 工作界面 |
| 项目网站 | 网站仓库 `deal-ops-site-dev`（私有开发仓库，本地 （本机路径，未公开），网页在 `site/`）；公开仓库 `deal-ops-site`，Vercel 从它部署 | 介绍页 |

网站 2026-11-02 起不在 Toolkit 仓库里（拆仓库方案 S7）：网址不变（https://deal-ops-toolkit-site.vercel.app），线上文件与搬家前逐字节相同。下文「网站仓库」都指 `deal-ops-site-dev`。

- **网站冻结，是视觉基准（v0.3）。** 网站现在的设计是负责人认可的，**不因本文件或两个工作界面的改动而变化**；网站只在负责人明确要求时改，按网站仓库的网站手册（`docs/08_SITE_HANDBOOK.md`）执行。以后新加的共用设计（颜色、字体、组件）以网站为准；工作界面只有在可读性、可用性这类功能原因下才可以不同，并在本文件写明理由。
- **设计变量（§2）两个工作界面完全相同。** 现有的值来自 Toolkit `src/index.css`。浅色模式的核心颜色、主按钮和两款字体与网站一致；深色模式的几个次要颜色和两种圆角与网站不同（§11.1），保持现状。
- **组件规则（§4）两个工作界面相同。** 网站另有介绍页专用的部分（首屏插画、动效、叠卡、渐变大字），只用在网站上（§6）。
- **改设计的流程（§10）：** 先改本文件，经负责人同意后，再改两个工作界面的样式。不在某一处单独改颜色、字体或组件样式。

本文件只写我们自己的规则。不出现其他产品或平台的名字、标志、文案，不用商业字体。

## 3. 字体

- **Inter**（可变字重）用于正文和标题；**IBM Plex Mono** 用于编号类内容：备注号、UETR、账号尾号、Case ID、段落小标签。
- 两款都是 SIL OFL 1.1 开源授权。字体文件和许可证原文随各自的界面一起发布（拉丁字符子集，`woff2`），**不连接任何外部字体服务**。本仓库放在 `src/web/fonts/` 和 `src/web/public/licenses/`，与网站仓库的 `site/fonts/`、`site/licenses/` 使用相同的文件（2026-11-02 核对：三个字体文件和两份许可证逐字节相同）。
- 字体栈：`'Inter Variable', system-ui, -apple-system, 'Segoe UI', Roboto, sans-serif`；等宽：`'IBM Plex Mono', ui-monospace, 'SF Mono', Menlo, Consolas, monospace`。
- 工作界面字号：正文 14px / 1.5；h2 32px / 40px、字重 300；h3 20px / 28px、字重 400；h4 15px、字重 500；小字和标签 12–13px。
- 细字重（300）只用在 24px 及以上。
- 金额一律 `font-variant-numeric: tabular-nums`，金额按币种加符号（£ € $），两位小数。

## 5. 邮件和模型文字的显示（Inbox 专有的安全规则）

- 邮件正文只显示纯文本，不渲染 HTML、不加载远程资源（PRD R-REV-02，技术方案 T9）；正文用 `<pre>`，保留换行，长行自动折行。
- 模型给出的理由和字段值是纯文本，**从不按 HTML 或 Markdown 渲染**（TC-REV-02）。
- 占位符：`[NAME_n]`、`[EMAIL_n]`、`[PHONE_n]`、`[ADDRESS_n]` 在界面上还原；`[ACCOUNT_n]`、`[SORTCODE_n]`、`[ID_n]`、`[DOB_n]` 永不还原，只显示说明（如「(account number)」）或掩码（「ending 5432」）（C-RED-2）。
- 风险旗标只在内部界面出现，从不进入回复文字（C-FRD-3）。

## 6. 只用在网站上的部分

首屏插画和面板、三步叠卡、渐变大字和信任数字、页脚字标、入场和轮换动效、短片，规则都在网站仓库 `docs/08_SITE_HANDBOOK.md` §3.2–§4。工作界面不用这些：工作界面只有 `--ease` 一种过渡，没有入场动画。

## 7. 深浅模式

- 默认跟随系统设置。
- Toolkit 的工作界面允许在页面上选择深浅色（`data-theme`，Toolkit 决定 9），网站不放切换按钮（网站决定 F）。Inbox 审核界面在 E2 只跟随系统；要不要加页面上的切换按钮，到 E5 打包时与 Toolkit 一起决定。

## 8. 无障碍（WCAG 2.2 AA）

- 文字对比度 ≥ 4.5:1（大字 ≥ 3:1）；焦点框对比度 ≥ 3:1，每个可操作元素都有可见的焦点。
- 状态不只靠颜色（§2.1）；标题层级完整；表单控件都有标签。
- 375px 宽度下没有横向滚动；可点击区域 ≥ 40px 高。
- 系统开启「减少动效」时不做任何过渡。

## 9. 文案

- 界面用英文，句子式大小写（只有首字母大写）；按钮用动词开头，例如「Sign in」「Copy reply」。
- 简短、具体；不出现内部风控用语（C-FRD-3 的内部用语表），因为它们可能被复制进回复。

## 10. 改动流程和检查

1. 先改本文件，写明改什么、为什么，经负责人同意。
2. 再改两个工作界面共用的 `tokens.css`（§11.2，两处内容逐字相同），以及需要改的组件样式：Toolkit `src/index.css`、本仓库 `src/web/styles.css`。**不改网站**（网站仓库 `site/`，§1）。
3. 检查：每个改过的页面截浅色、深色、375px 三张图；Inbox 的浏览器测试（TC-REV-01、02）和 Toolkit 的 E2E 都要通过；对比度用工具量一遍。
4. 记录：在本文件末尾的变更记录里写一行。

### 11.2 共用变量文件 `tokens.css`

- Toolkit 应用和 Inbox 各有一个 `tokens.css`，**内容逐字相同**，只含 §2 的共用变量：浅色和深色两套颜色、圆角、控件高度、阴影、过渡、字体栈。文件开头注明来源和「两处逐字相同，改动按 §10」。网站不引用它，保留自己的样式（v0.3）。
- 应用和 Inbox 的样式只引用这些变量。网站专用变量（柔光、渐变、深色通栏、`--soft` 等）留在网站自己的样式里（v0.3）。
- 两个仓库的 CI 各有一个小检查：`tokens.css` 的 SHA-256 等于本文件里记录的值。有一处被单独改动时 CI 失败，提醒先改规则。
- **当前 `tokens.css` 的 SHA-256：** `fe9ab88bad1d4a6cfb33db518650f1da983e844fff267525d7f3237fe89b10a9`（改 `tokens.css` 时同时改这一行；Inbox 的检查脚本 `scripts/check-tokens.mjs` 读的就是这一行）。
